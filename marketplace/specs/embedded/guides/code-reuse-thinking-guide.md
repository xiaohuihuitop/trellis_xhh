# 代码复用思考指南

> 在 MCU 固件项目里，先判断"应不应该复用"，再决定"怎么写"。

---

## 写新代码前先检查

- 先搜有没有现成模块已经负责这类行为（`grep -r "关键词" .`）
- 先看是不是已有事件分支或 Task 模块可扩展
- 改常量、枚举、协议字段前，**先全局搜索所有引用**

---

## 跨项目参考实现库

项目参考根目录固定为：`D:\workspace\xhh_项目参考`。

- 该目录是只读参考库；当前项目不得通过相对路径引用其中源码，必须保持独立编译。
- 根目录下可放置多个项目，每个一级子目录为一个独立参考项目；项目数量不设限制。
- 参考项目应保留其 `.git` 信息或在项目根 `README.md` 中记录版本，确保可追溯到具体 commit 或稳定分支。
- 当前根目录为空时，不创建伪造参考代码；待实际项目放入后再参与检索。

### 开发前的复用顺序

1. 先检查当前项目是否已有职责匹配的模块，优先扩展现有模块。
2. 当前项目没有合适实现时，在 `D:\workspace\xhh_项目参考` 的各项目中检索同类实现。
3. 选定一个职责、接口和硬件条件最接近的参考项目作为本次来源；不得拼接多个项目的硬件底层实现。
4. 复制所需文件到当前项目后，按当前项目的 `xhh_BSP`、Components 和 Module 接口做最小调整。
5. 依据当前硬件资料、Project 配置和 BSP 实现完成核对、编译和上板验证；参考项目不能替代当前项目的硬件事实。

### 复用边界

| 代码类别 | 复用方式 |
|----------|----------|
| 纯算法、状态机、协议解析 | 优先原样复制，保持公开接口和行为一致。 |
| `xhh_Module` Task | 复用职责边界和业务逻辑；仅适配当前项目已有的 BSP/Components 接口。 |
| Components | 复用器件驱动或通用组件；硬件访问仍只能通过当前项目 `xhh_BSP`。 |
| `xhh_BSP` | 复用接口设计和已验证流程；必须重新核对并调整 MCU、时钟、引脚、ADC、Flash、IRQ 等当前硬件实现。 |
| `Platform`、厂家 HAL、启动和链接配置 | 不跨项目直接复制；仅按当前 MCU 的厂家资料和工程配置维护。 |

### 来源追溯

每次跨项目复制或修改参考实现时，在当前任务记录或提交说明中至少记录：

- 来源项目名称和相对路径
- 来源分支或 commit
- 被复用的文件或模块
- 为适配当前项目所作的硬件与接口调整

禁止只因文件同名而直接覆盖当前实现；禁止把参考项目中的 `Platform`、厂家类型、真实引脚、HAL 调用带入 `xhh_Module` 或 Components。

## 本项目的复用边界

| 已有模块 | 负责的行为 | 扩展方式 |
|----------|-----------|----------|
| `xhh_Task_Flash` | 所有 Flash 读写 | 加字段进结构体，不要散写 Flash |
| `xhh_Event` | 多模块联动 | 加事件枚举 + case，不要跨 Task 直调 |
| `xhh_Mode` | 系统状态 | 加状态枚举 + Change，不要另建状态机 |
| `xhh_Task_<X>` | 单一功能域 | 加 `_Cmd/_Loop/_Set_*` / `_Apply_*`，不要在 main_task 堆逻辑 |
| `xhh_BSP_Flash_Read/Write/Erase` | Flash 原语(BSP 层) | 经 `xhh_Task_Flash` 调,不另封装 |

## 常见重复陷阱

| 陷阱 | 错误做法 | 正确做法 |
|------|----------|----------|
| 协议入口写业务状态更新 | 在 `BLE_HANDLE.c` 里改 motor/ui/timeout | 走事件层统一协调 |
| 多个 Task 各自写 Flash | Motor/BAT 各调 `xhh_BSP_Flash_Write` | 集中到 `xhh_Task_Flash` |
| 重复的命令拼包逻辑 | 多处复制 | 抽到协议层 |
| 重复的范围校验 | 多处写同一 min/max 检查 | 抽 `IS_Valid` 谓词 |
| 新建功能不建 Task 模块 | 在 APP 主循环或 `main_task.c` 堆逻辑 | 建 `xhh_Task_<X>`，只提供真实业务接口，不加 Init/DeInit |

---

## 推荐判断

- 已有边界清晰的模块存在 → 优先扩它
- 同一逻辑出现 3 次以上 → 考虑抽公共 helper
- 只有一次使用且改成抽象更难懂 → 不要过度抽象
- 改常量/枚举前 → **必须** grep 全局引用，避免"忘了改 X"bug

---

## 改常量前必做

```bash
# 搜所有引用，确认没有遗漏
grep -r "要改的值" .
grep -r "要改的宏名" .
```

这一个习惯能挡住大多数"忘了更新 X"的 bug。
