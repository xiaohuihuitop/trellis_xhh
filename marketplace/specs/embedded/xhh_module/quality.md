# 质量规范

本文件只约束源码格式、编码、注释和可静态审查的代码质量。构建、烧录、实物验证和项目事实核对由全局 `xhh-mcu-development` Skill 处理。

## 代码格式

| 项 | 规则 |
|----|------|
| 缩进 | 统一 Tab |
| 大括号 | 延续当前代码库的既有风格 |
| `case` | 顶格，不缩进 |
| 文件头注释 | 不写，依靠 Git 记录历史 |
| 缩写词 | 全大写，例如 LED、USB、BLE、ADC |

## TODO 注释

需要后续处理的事项使用单行 TODO，并使 `TODO` 成为注释的第一个词：

```c
//TODO 标定温度阈值
// TODO: VCC 需确认
```

- 使用 `//TODO`、`// TODO` 或带冒号的等价形式。
- 一行只记录一个 TODO，不把 TODO 嵌入多行注释正文。
- 可用 `rg -n '^\s*//\s*TODO(?::)?\b'` 定位。

## 注释边界

源码注释只说明代码行为、非直观原因和修改约束，不维护第二份硬件或产品事实。

- 对外函数使用中文 Doxygen 注释，说明接口作用、参数、返回值和前置条件。
- 关键逻辑和占位函数使用中文 `AI:` 注释，说明当前行为、原因和启用条件。
- `xhh_BSP` 头文件不写当前平台、板卡、端口、引脚、极性或厂家资源。
- `xhh_Module` 注释描述业务状态、事件、周期、算法和数值语义，不描述 MCU 或板级资源。
- `Components` 注释描述器件协议、命令时序和数据处理，不描述产品状态或板卡连接。
- 单函数内的数值注释说明单位、计算含义和修改条件。

## 数值配置位置

- 只服务单个函数的少量业务数值直接写在使用位置，并以 `AI:` 注释说明含义和修改条件。
- 单函数内的阈值表、标定表使用 `static const`，表前说明排序和元素边界。
- 跨函数共享的公开常量、协议字段、编译开关和数组容量才使用命名宏、枚举或文件级 `static const`。
- 禁止无含义注释的裸数值，也不把单函数标定值拆到无关的宏定义区。

## 文件编码

- `.c/.h` 使用 UTF-8 无 BOM 和 CRLF 行尾。
- 编辑历史非 UTF-8 文件前先转为 UTF-8，修改后不再转回旧编码。
- 新建源码文件不写文件头注释，保持 Tab 缩进。

## 必须遵守

- 模块内部状态默认使用 `.c` 内私有 `static` 变量或 context；跨模块数据必须有明确归属，外部只按约定读取。
- 持久化数据应用前必须校验。
- 占位函数允许用于框架统一，但必须明确注释，且不得返回默认成功、伪造硬件值或执行静默 fallback。
- 不为不需要的统一外形增加接口、动态内存或平行实现。

## 静态检查

- [ ] 改动遵守目录边界，未引入反向或循环依赖。
- [ ] 新增公开接口有 Doxygen 注释，关键逻辑有必要的 `AI:` 注释。
- [ ] 源码没有无说明占位、测试 Hook、调试残留或静默 fallback。
- [ ] 枚举、数组下标和参数范围在所属接口边界处理。
- [ ] 代码保持 UTF-8 无 BOM、CRLF、Tab 和既有命名风格。
